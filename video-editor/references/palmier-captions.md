## TL;DR
Palmier has **rich, native captioning** and supports **multiple kinds** — far beyond DaVinci. Auto-captions are styleable on creation, and because caption clips are *real timeline clips*, they're also **editable, restyleable, retimeable, and animatable** afterward. Word-level/karaoke captions are constructible from the word-level transcript.

## How captions appear in the model
`get_timeline` returns caption clips sharing a `captionGroupId` as **`captionGroups`** — common style hoisted into `shared`, each cue a `[clipId, startFrame, durationFrames, text]` row (capped at 200 rows; page with start/endFrame on long timelines). Caption clips whose style deviates appear individually under `clips`.

## Recipe (v0.6.1)
1. `get_timeline` — captioning/transcription works even when `canGenerate` is false (local fallback).
2. Put a clip with speech on the timeline (`import_media` → `add_clips`).
3. `add_captions({fontName:"Helvetica-Bold", fontSize:54, color:"#FFFFFF", centerY:0.8, animation:"highlightPop", highlightColor:"#FFEE00"})` — omit `clipIds` to caption the whole spoken track.
4. Verify: `get_timeline(startFrame,endFrame)` → inspect the `captionGroups` (text + style + `textAnimation`); `inspect_timeline` to *see* the burned-in captions (sample mid-word for the highlight).
5. Fix ASR errors: `update_text({clipIds:[cueId], content:"Klarna"})` per bad cue (keep ≤20 chars for single-line at 54pt/1080-wide). Restyle or re-animate the whole group in one call via `captionGroupId`.

## Captions are Palmier's, full stop

Palmier owns captioning: free-form styling on creation, post-hoc restyling, per-cue text edits,
word-level/karaoke, and animation. There is no reason to route captions elsewhere — Resolve's
scripting API can only auto-transcribe into a default-styled subtitle track it cannot then edit,
style, or word-level (all UI). **Caption length rule of thumb, any backend:** caption width is set
by aspect ratio, so check the canvas orientation before captioning — on a 1080-wide vertical canvas
at 54pt the single-line budget is ~20 chars (see above); horizontal 16:9 fits roughly double.
